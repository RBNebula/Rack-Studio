# Device designer and perforated tray reference

Use **Device Model Designer** for an isolated 3D workspace. It uses the same document layout as the report workspaces: the header holds **New model** and **Edit library model**, a **Model properties** card holds name and dimensions, the **Face editor** card holds the Design front / Design rear switch, the component palette and the face editor, the **3D preview** card accepts drops too, and **Save model to library** / **Save as new** stay in the bar at the bottom. Enter U height, chassis width below 457.2 mm (18 inches), and ear-plane-to-rear depth. The separate rack installation check still enforces the configured rack's clear opening; 18 inches is an authoring ceiling, not a universal fit guarantee. Ears use the nominal 482.6 mm overall width.

Select **Design front** or **Design rear**. Drag a palette component onto the 3D chassis or the face editor. Components already on a face can be moved by dragging in the face editor; selected ports can be renamed and components removed. Save the model to the project library, then place it through the normal rack library. Editing an existing library model retains its stored appearance, images, parts and port metadata; the designer preview remains schematic. **Save model to library** updates that definition. To make a variant, choose **Save as new**, enter a distinct model name, and save. The variant receives a new definition identity; the original and its installed devices/cables stay unchanged. The editor switches to the new copy, so later ordinary saves update that copy. Blank or existing names are rejected, and Cancel keeps your draft edits. Connected port IDs stay scoped to their own device definition. Save before leaving the designer; uncommitted editor drafts are not project records.

The starter palette includes RJ45, USB-A/C, HDMI, DisplayPort, VGA, PS/2, audio jack, IEC power, LC, SDI and DC sockets, plus fans and grilles. Socket centres become real routable endpoints. Fans and grilles are visual features and never appear as cable endpoints. These are schematic components; connector shells, fan cutouts and grille airflow are not engineered physical simulations. Overlapping components are currently allowed; check the layout visually. Out-of-face placement prevents saving. Chassis and decorative feature dimensions can still require calibration.

Drag **Perforated PVC cable tray** from the rack library into the rack viewport, or add a cable tray from the rack tools. Position and size remain editable in the inspector. Select it and drag the green far-end handle in a suitable 3D or top view to change the cut length; its near end stays fixed. Camera projection must expose the length axis. Hide a rack cover if it obscures the tray. A single cut section supports 40–2000 mm length in 10 mm handle steps. Add another section for a longer installation.

The tray follows [Penn Elcom PCT110](https://www.penn-elcom.com/2000mm-x-110mm-black-plastic-cable-tray-pct110): the supplier specifies 2000 mm supplied length, 110 mm width, black finish and 2.5 mm PVC, designed for cutting. The initial 400 mm cut, 17 mm lip height, 12 × 24 mm rectangular slots and 40/25 mm repeating pitches are **provisional examples**, not a measured PCT110 drawing. Extending the model adds complete fixed-size slots at the far end. Existing holes retain their dimensions, pitch and distance from the fixed end. Slots render as real holes; routing conservatively treats the tray floor and walls as solid. The [modelling workspace](modelling-workspace.md) now adds movement/rotation, surface attachment, physical clips/ties and bound tray routing. Actual bracket hardware, slot-aware cable passage, section joiners and flexible fixing dynamics remain future work. Legacy trays retain their previous geometry until deliberately replaced.

The user-annotated PC photo confirms DisplayPort above HDMI, five rear USB 2.0 sockets, one rear USB 3.0 socket and 1G RJ45. The bundled PC definition now records those labels; positional evidence and 43 mm physical height remain provisional. Existing project definitions are not silently rewritten. The updated PC reference library can be imported independently.

## Rotate a connector

Select a socket in the face editor. Below it, use **Rotate connector 90°** for quarter turns, or **Connector rotation (°)** for an exact angle. Positive angles turn clockwise when looking at the connector face, consistently on both front and rear. Four quarter turns return to zero. The 3D preview and face editor update together. Fans/grilles remain separate decorative components.

For an existing definition, **Device Library → Edit → Ports** provides the same angle and quarter-turn controls on every port row. Save normally to update that definition, or use **Save as new** in the designer to retain the original. Angles survive project/library JSON exports, copies, undo/redo and local save/reopen. Legacy ports retain zero rotation without requiring conversion.

Rotation turns the connector around its centre. Its stored size stays unchanged; the rotated footprint is checked against the chassis face in the designer. The rack port marker and click target turn with it. The photographed PC and generic switch also rotate their rendered shell openings and preserve their original detail around the opening. Cable connection identities, centres and outward exit directions remain unchanged. Connector aiming/direction is a separate property.
